# 「構成と接続」の操作と接続根拠

## Scope

製品自身の構成図と、利用者が読み込んだ構成ファイルの表示を対象とする。[Task 20261123-09](../tasks/TASK.architecture-canvas-11-23-2026.md)

## Acceptance Criteria

- 箱を動かすと、接続線の端点が追従する。余白のドラッグは図全体を移動する。
- 表示を拡大・縮小できる。全体表示で今の配置を見渡せ、自動配置に戻せる。
- 線を選ぶと接続元・接続先・理由・根拠を読める。同じ向きの2要素間に複数の記録があれば全件を表示し、根拠が未記録のときはその旨を示す。

## Evidence

[操作試験](../../tests/browser/architecture-canvas.browser.mjs)はChromeで製品構成の11要素・16接続を開き、ノードの座標、線の経路、表示範囲、詳細欄の内容を確認する。スマートフォン幅はChromeのタッチ入力エミュレーションを使う。図の移動と拡大の操作はdraw.ioの[キャンバスの移動](https://www.drawio.com/docs/manual/editor/pan-scroll/)と[表示倍率の操作](https://www.drawio.com/docs/manual/editor/zoom/)を参考にした。

## Verification Result

Chromeの1440px幅と390px幅で、同方向に重なる2つの接続記録に「利用者入力」と「内部処理」をそれぞれ設定し、受付フォームの入力範囲を書き込んだ。保存したJSONを再読込し、部品の接続一覧から開いて区分・範囲・既存の根拠が一致した。すべて内部処理の線は破線、利用者入力を含む線は青い実線になり、指定を解除すると既定の線に戻った。[見本の編集画面](../evidence/architecture-canvas-20261123/ui-input-route.png)・[保存と再読込の操作試験](../../tests/browser/architecture-canvas.browser.mjs)

Chromeの1440px幅と390px幅で、検証用の構成ファイルを画面から読み込んだ。請求APIのカードにはCritical 1件・High 2件・Medium 1件・Low 1件が重大度順に収まり、詳細の5件と色・件数が一致した。別の部品の情報1件は灰色で表示され、指摘がない部品のバッジは0個だった。[検証用のカード](../evidence/architecture-canvas-20261123/triage-card.png)・[ブラウザー試験](../../tests/browser/architecture.browser.mjs)

製品構成図をChromeで開き、提示画像と同じ約704px幅の図で、両方の表示モードとも切り替え・倍率・配置操作が1行に収まった。画面幅390pxでは全操作が横スクロールなしで収まり、320pxでは操作列だけを横にスクロールして最後のボタンまで表示できた。製品の図の見出し、検証報告と集計部品の説明が非表示であることも確認した。

デスクトップのChromeで修飾キーを押さずに図の上でホイールを回し、上方向で拡大し下方向で元の倍率に戻ることを確認した。拡大前後でポインター下の図の座標のずれは0.01単位未満で、ページのスクロール位置は同じだった。図の外でホイールを回すとページが移動し、図の倍率は維持された。

1440pxでマウス、390pxでタッチドラッグ・ピンチを確認した。両方で「モニター・判断画面 → 読み取りAPI」の線を選び、表示された接続理由と根拠が元データに一致した。重なっている線はタップ位置に近い順で選べる。キーボードでの箱の移動・線の選択、別ファイルを開いたときの配置リセット、同じ線上の複数記録も確認した。[接続を選んだ画面](../evidence/architecture-canvas-20261123/connection.png)

[既存の操作試験](../../tests/browser/architecture.browser.mjs)は同じ2画面幅で成功した。見本・利用者のファイル・CloudFormation・package.jsonの入力、絞り込み、部品の指摘を確認した。[構成データの単体試験](../../tests/architecture.test.mjs)は6件成功した。
