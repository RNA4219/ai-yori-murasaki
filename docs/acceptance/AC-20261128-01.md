# Obsidian の課題取り込みの技術検収

## Scope

[R-092](../tasks/TASK.obsidian-issues-11-28-2026.md) の対象は、操作者が指定する1つのノート、案件と実行への課題の登録、判断画面の出典、照合レポート。架空のローカル vault と観測を使う。

## Acceptance Criteria

| T64 の操作 | 期待する結果 |
| --- | --- |
| ノートを指定して CLI から取り込む | 通常のチェックボックスを1行1件で登録する。未チェックは `open`、チェック済みは `done`。引用やコード例を件数に含めない。 |
| 同じノートを再送し、続いて既存の識別子で状態を変えて再送する | 同じ内容は登録済みとして数える。変更が衝突した場合は今回の追加をすべて取り消し、確認済みの記録を保持する。 |
| 指定外のパスや有効な課題のないノートを渡す | エラーを返し、案件の課題を追加しない。 |
| 判断画面から課題を選んで原本の所在を確かめる | 題名・状態と Obsidian の出典を確認できる。出典リンクは選んだ vault の相対ノートを指す。 |
| 観測を取り込み JSON・CSV・Markdown で照合結果を読む | Obsidian の課題が照合対象になる。範囲を指定しない課題で資源の不在を推定しない。 |
| 同じ案件に Notion CSV の課題を登録し、ノートを参考資料にも取り込む | 両方の課題を区別して読める。参考資料として保存したノートの本文を資料の一覧から開ける。 |
| Blue の画面・API で案件と照合結果を開く | ノートの課題や出典を開示しない。照合 API の応答は `{"status":"withheld"}`。 |
