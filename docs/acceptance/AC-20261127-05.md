# Google ログインのドメイン許可の技術検収

## Scope

[R-090 の設定](../requirements/GOOGLE-MONITOR-SSO.md)を使って起動したローカルモニターに対し、署名済みの合成 ID トークンとブラウザーで T62 を検証する。[Task 20261127-05](../tasks/TASK.google-sso-email-domains-11-27-2026.md)

## Acceptance Criteria

| T62 の条件 | 期待する結果 |
| --- | --- |
| 個別のアカウントだけを設定する | 従来と同じ `openid profile` を要求し、許可した `sub` があればメールのクレームがなくてもログインできる。 |
| `example.com,example.org` だけを設定する | `openid email` を要求する。検証済みのメールドメインと `hd` が同じ許可名に完全一致する Workspace アカウントが通る。 |
| サブドメイン、別名、所属情報の欠落、メールが未確認のアカウントを使う | 完全一致または確認済みの条件を欠くため通らない。文字列の `"true"` も確認済みとして扱わない。 |
| 個人用 Gmail を使う | ドメインで許可するには `gmail.com` の明示指定と確認済みメールが必要。 |
| 個別の `sub` とドメインの両方を設定する | 両条件を満たした場合だけ通る。一方だけが一致しても保護対象のデータは取得できない。 |
| 両方とも未設定、または空項目・ワイルドカード等を含む設定で SSO を起動する | `google_sso_configuration` を返し、サーバーを開始しない。 |
| モニターの Blue 画面からログインする | 許可時は元のビューに戻り、既存の Blue の表示範囲が維持される。拒否時は保護データを表示しない。 |

## Evidence
