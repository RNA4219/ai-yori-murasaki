# 課題 CSV と観測を使った技術検収

## Scope

[Task 20261126-01](../tasks/TASK.offline-tracker-drift-11-26-2026.md) のローカル取り込み・照合・根拠表示・書き出し。入力は合成した Notion 形式の CSV と資源・検知の JSON とする。

## Acceptance Criteria

| 試験 | 確認事項 |
| --- | --- |
| T43 | 課題ごとの分類と、照合できない理由が合成データの期待値に一致する。 |
| T44・T45 | 必須の出典情報がない観測を拒否する。外部接続や課題管理サービスの認証情報を使わず、照合前後で原本と保存済みの記録が変わらない。 |
| T46・T47 | 推定・確定の区別、古い観測の印、照合不能の内訳を確認できる。 |
| T48 | 判断画面で一覧と候補の行を開く2操作で根拠に到達する。書き出した表に分類、結び方、取得日時が載る。 |
| 課題 CSV の入り口 | CSV から取り込んだ課題が CLI・API・画面に現れ、同じ行を再送しても課題が増えない。 |

## Evidence

照合の期待値は[分類試験](../../tests/test_tracker_drift_matching.py)に、案件への取り込みと CLI の結果は[CLI 試験](../../tests/test_tracker_drift_cli.py)に記録する。[API の境界試験](../../tests/test_tracker_drift_api.py)では Blue に対する非公開と応答上限を確認する。

[CSV からの通し試験](../../tests/test_tracker_drift_e2e.py)は、案件と Run を CLI で作成し、BOM 付きの課題 CSV と観測3ファイルを取り込む。次のコマンドで再現できる。

```sh
python -m unittest discover -s tests -p test_tracker_drift_e2e.py -v
```

## Verification Result

通し試験は1件成功した。課題8件について5つの分類と照合できない4つの理由、同じ CSV を再送したときの課題 ID と件数、CLI と API の結果の一致、Blue での非公開を確認した。照合前後で原本・保存済みファイルのハッシュも一致した。

[操作ガイド](../NOTION-IMPORT.md)の例も実際に取り込んだ。課題2件のうち1件が「一覧は解決、検知が残る」、もう1件が「観測の範囲外」となり、Markdown・CSV に検知 ID が出力された。
