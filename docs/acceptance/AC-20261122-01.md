# 判断の画面と記録モニターの技術検収

## Scope

[改修要件](../tasks/TASK.frontend-review-11-22-2026.md)に基づく、読み取り専用の2画面とその間の移動。画面には製品サーバーから配信したHTMLと、試験用に用意した案件・公開記録を使った。

## Acceptance Criteria

- [x] 「案件のつながり」で前回と今回の記録を開ける。架空の4案件で、一覧の比較元と各案件の判断画面の比較元が一致した。3案件からなる2組と比較相手のない1案件を表示し、個別表示・全件表示を往復できる。

- [x] 判断すべき件数と未完了件数が先頭に出る。判断が必要な課題では開く前に次の行動を読み、行を開くと理由を確認できる。評価範囲の注意事項も同じ画面で読める。
- [x] 案件一覧と検知本文を左右に並べる1440px幅でも、一列に並べる390px幅でも、案件選択で本文が切り替わる。空の案件に移ると前の検知名は消える。390×844pxの見本で証跡へのリンクが初期画面内に入る。
- [x] 案件を保って画面を往復できる。案件の記録を読み直して非公開となったとき、以前の課題は表示されない。
- [x] 「すべての課題」から全件を表示できる。モニターを更新しても、開いた接続状態の詳細は開いたままになる。
- [x] キーボードから本文をスキップしても対象案件を保つ。動きを減らす設定で詳細を開ける。ローカルファイルで同梱JSONを選択して読める。
