# モニターのログイン画面の技術検収

## Scope

[Task 20261128-04](../tasks/TASK.monitor-login-screen-11-28-2026.md) に従い、SSO が有効なローカル HTTPS モニターを、合成の認証サービスとアカウントで開く。[ログインの利用手順](../requirements/GOOGLE-MONITOR-SSO.md)

## Acceptance Criteria

- 初回、キャンセル、許可対象外、認証サービス利用不可の各画面で、製品名、状態ごとの案内、「Google でログイン」が同じ順番で現れる。
- PC 幅とスマートフォン幅でカードとボタンが画面に収まり、案内の全文が読める。Tab キーで操作位置が見え、Enter キーでログインを開始できる。
- ログイン画面の読み込みに外部サービスを必要としない。許可したアカウントは元の Blue 画面へ戻れ、ログアウト後は再認証を求められる。

## Evidence

Google 認証、モニターの認証、HTTPS の3ファイルに対し `pytest` を実行した。27件とサブテスト68件がすべて成功し、終了コードは0だった。[Google 認証の試験](../../tests/test_google_sso.py)・[モニターの認証試験](../../tests/test_monitor_auth.py)・[HTTPS の試験](../../tests/test_monitor_tls_transport.py)

`node tests/browser/google-sso.browser.mjs` は、個別許可（幅1440・375・320 px）、ドメイン許可（幅1440・375 px）、両方を指定（幅1440・375 px）の7条件で成功した。暗い配色と強制カラーも含めて、キーボードフォーカス、文字の重なりや欠け、認証、3種類のエラーからの再試行、Blue の4画面とログアウトを確認した。幅1440・375 pxで初回の見出しは1行、許可対象外の見出しは2行で読めた。[Chromium でのログイン操作](../../tests/browser/google-sso.browser.mjs)

独立レビューでは各状態の CSP、キャッシュ禁止、同一オリジンのログインリンク、およびブラウザー試験が文字の重なりや欠けを検出する条件を確認した。

利用手順の日本語を Yomiyasu の `run` と `verify` で検査し、ボタン名、操作順、再試行の条件を画面と照合した。
