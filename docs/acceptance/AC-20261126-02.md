# 課題の照合条件と資源の在否に関する技術検収

## Scope

[Task 20261126-02](../tasks/TASK.tracker-evidence-11-26-2026.md) の対象は、合成した課題 CSV と観測 JSON を取り込んだ案件。CLI、判断画面、案件の drift API、Markdown と CSV の書き出しを確認する。

## Acceptance Criteria

| 試験 | 入力と期待値 |
| --- | --- |
| T49 | 同一資源に課題に関係する解決済み検知と、別ルールの有効な検知を与える。前者に絞った完了課題は整合し、採用したルールを確認できる。対応を外すと全検査を使用した印が付き、残存検知を示す。 |
| T50 | 課題にアカウント ID、明示した除外語に一致する資源、通常の資源を書く。通常の資源が根拠に残り、除外件数から取り除いた資源を数えられる。 |
| T51 | 同じ ID の異なる種類に別々の検知を与える。種類の分かる検知は対応する資源だけに結び付く。種類が決められない検知だけでずれは確定しない。 |
| T52 | 収集対象外の資源の在否は不明。本文だけの ID は、指定した書式と種類が合い、課題と観測の提供元・アカウント・地域が対応するときだけ不在にできる。範囲が不明な課題と、書式を省いた従来入力も検証する。 |
| 既存入力 | 種類なしの検知と従来の資源一覧を取り込める。ID が一意な資源の分類、候補から根拠への操作と Blue ビューの非公開を確認する。 |

## Evidence

[操作例](../NOTION-IMPORT.md)で検査の絞り込みと本文の ID の在否を再現できる。課題・観測の取り込みから照合結果までの[通し試験](../../tests/test_tracker_evidence_workflow.py)は、次のコマンドで実行する。

```sh
python -m pytest -q tests/test_tracker_evidence_workflow.py
```
