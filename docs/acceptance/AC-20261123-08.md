# 案件の重要度別件数から検知の明細を開く

## Scope

選んだ案件のモニターと判断画面が対象。元の検知に記録された重要度ごとに、対応済みを含む全検知を数える。集計単位は案件内で一意の検知ID。[作業要件](../tasks/TASK.case-severity-11-23-2026.md)

## Acceptance Criteria

- 重要度別の件数を押すと、その重要度・案件に一致する検知を表示する。先頭4件の抜粋にない検知も含める。
- 未集計と確認済み0件を区別する。一部未集計は確認できた内訳を示し、重要度が記録されていない検知は「未記録」とする。
- 一覧の件数の表示と、読み込み済みの案件内での絞り込みのために台帳を追加で開かない。

## Evidence

[検証プログラム](../../tests/fixtures/verify_case_severity.py)は専用ストアを作り、1案件に8件の記録を置く。検知IDの重複が1件あるため、期待する総数は7件。重要度「高」の2件はともに一覧の抜粋の範囲外で、片方は対応済み。重要度「情報」と「未記録」は各1件とする。

実際のサーバーとChromiumで、Enterによる選択、対象の件名、選択中の表示、ブラウザーの「戻る」、全件への復帰を確認する。判断画面では既存の検索語とフィルターを先に設定し、件数を押した時点で該当する2件が両方表示されることを確認する。Pythonの監査フックで開いた台帳の実行IDを記録する。WSL2のext4でPythonの製品依存、Playwright 1.65.2と付属Chromiumを用いて実行する。

```sh
PYTHONPATH=. python tests/fixtures/verify_case_severity.py --count 100000
```

## Verification Result

10万案件のストアで、1440pxと390pxの両方で終了コード0。選んだ案件の「高 2件」から「退職者アカウントの停止記録」と「委託先アカウントの有効期限」を表示できた。判断画面でも同じ2件が開いた。両画面とも無関係な案件の台帳の読み取りは0本。読み込み済みの詳細で重要度を切り替えたときも台帳の追加読み取りは0回だった。[一覧の表示](../evidence/case-severity-20261123/campaign.png)・[デスクトップの明細](../evidence/case-severity-20261123/detail-1440.png)・[スマートフォンの明細](../evidence/case-severity-20261123/detail-390.png)

[索引の回帰試験](../../tests/test_monitor_index.py)で、v2からの通常の更新時に未変更の台帳を開かずに内訳を復元した。未集計・一部未集計・確認済み0件、重要度変更後の差分更新、Blueへの応答に内訳を含めないことも確認した。
