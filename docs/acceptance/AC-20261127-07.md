# モニターの HTTPS と再診断で修正した5箇所の技術検収

## Scope

[R-091](../tasks/TASK.monitor-https-11-27-2026.md) の起動と認証を、合成した証明書・アカウントとローカルブラウザーで確認する。対象は `aym monitor serve`、モニター4画面、API、Google ログインの開始・戻り先・ログアウト。

再診断では Blue ビューの継承、LLM 通信の受信上限、案件受付台帳の SQLite と PyO3、Obsidian の設定フォルダー除外、実行台帳の整合性確認も対象とする。

## Acceptance Criteria

| T63 の条件 | 期待する結果 |
| --- | --- |
| 通常の CLI に証明書と鍵を指定して起動する | ループバックで HTTPS を提供する。クライアントは信頼した CA と `127.0.0.1` の IP SAN を使って接続先を検証できる。 |
| 証明書と鍵が未指定・片方のみ・読取不能・不一致 | エラーを返し、平文で待ち受けを開始しない。 |
| 非 SSO で `--allow-http-loopback` を明示する | ローカル HTTP で利用できる。SSO または TLS 設定と併用すると起動しない。 |
| Google ログインを有効にして認証を開始する | 開始時とコード交換時の `redirect_uri` は登録した同じ HTTPS URL。認証用の Cookie には `Secure`、`HttpOnly`、`SameSite=Lax` が付く。 |
| HTTPS の4画面・APIをログイン前後、ログアウト後と期限切れ後に開く | 従来の許可条件・Blue の表示範囲を保ち、セッション失効後は再認証を求める。 |

| 再診断で修正した箇所 | 期待する結果 |
| --- | --- |
| Blue の画面から資料と実行履歴を開く | 元のビューを API へのリクエストに引き継ぎ、Blue に公開しない資料や履歴の識別情報を表示しない。 |
| vault の設定フォルダーと通常のノートを取り込む | `.obsidian` と同名のフォルダーは大小文字や深さにかかわらず拒否し、カタログに追加しない。名前が似ているだけの通常フォルダーは対象にできる。 |
| モニターから実行イベントを読む | 台帳の整合性を確認できない場合は 409 `evidence_unverified` を返し、そのイベントを画面に表示しない。有効な旧台帳は従来の順序・投影で読み、初回記録前の実行中の Run は空配列を返す。 |
| ローカルでチャンク分割された LLM 応答を読む | 設定した受信上限内の応答を読める。上限を超える受信は打ち切る。 |
| 案件受付のネイティブ拡張を含む配布物で台帳を読み書きする | 入力の登録と読取が同梱の修正版 SQLite を使い、既存の受付台帳を引き続き参照できる。RustSec の3件の対象依存が修正済みの版であることを確認する。 |
| Windows で同じ入力を4プロセスから初回登録する | 4件とも成功し、同じ受付情報を返す。台帳を検索すると該当する受付は1件。 |
