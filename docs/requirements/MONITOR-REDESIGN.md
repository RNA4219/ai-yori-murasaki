# モニターの再設計

ユーザーの画面デザインへの指摘と、自動更新時の読み込み表示をなくす要求に対応する。[Task 20261107-01](../tasks/TASK.monitor-redesign-11-07-2026.md)で扱い、製品の読み取り専用APIと評価条件は維持する。

## 画面の参照と採用方針

2026-11-07に[LinearのProjects画面](https://linear.app/docs/projects)と[VercelのObservability画面](https://vercel.com/docs/observability)を検索し、両社の公開画面を確認した。Linearから固定ナビゲーションと行を中心にした一覧、Vercelから主要数値と詳細の表を分ける構成を参考にした。画像やコードは製品へ転用していない。

GLMに `ai-instructions-frontend` の本文と、layout-code・interaction・delivery-qualityの参照文書を渡して設計した。実装はOllamaの `deepseek-v4.1-flash:cloud`、レビューは `glm-5.3:cloud`。監督側が差分の整合とブラウザーの実表示を確認する。

## レイアウト

- 2026-11-09のユーザー指示で、白基調と薄い区切り線へ変更した。紫はブランドと選択位置、警告にはアンバーを使う。本文18px、補助文・表・ボタン16px以上、見出し24pxを基本とする。[追加検収](../acceptance/AC-20261109-02.md)に実測を記録する。
- デスクトップでは240px幅のサイドバーを固定する。モバイルではメニューを折りたたむ。
- Campaignの属性を横に並べ、証拠の完全性・検知率・適合率・修復成功率を上部へ配置する。数値には既存の検証処理を使う。
- 概要・実行履歴・RSIをボタンで切り替える。概要では検知の本文をIDより目立たせ、修復の実状態を表示する。
- 全11指標は詳細を開いて確認する。測定の限界は概要に常時表示する。HOLD・未測定・形式不正を数値と区別する。
- 外部フォント、画像、スクリプトへの依存は追加しない。数値やグラフを補作しない。

## 自動更新

15秒ごとに裏で取得し、同じ対象の表示を取得開始時に消さない。DOMを差分更新し、変更がないノード、フォーカス、スクロール、詳細の開閉、選択中の表示を保持する。更新処理は重複実行を抑える。

同じ対象の再取得に失敗した場合は、前回成功時のデータを残して警告を出す。一部の取得だけ失敗した場合も、その一覧が古いことを明示する。対象を切り替えた場合は前の対象の表示を引き継がず、古い応答を世代番号で除外する。非表示タブでは更新を休止し、復帰時に一覧と詳細を取得する。

## 検証

実APIでの表示と自動更新、API応答を差し替えた異常系、画面幅1440・768・390px、キーボード操作、axe-coreを確認する。機能の確認と、ユーザーによる見た目の評価を区別する。[検収記録](../acceptance/AC-20261107-01.md)へ結果を残す。
