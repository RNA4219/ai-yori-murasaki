# 案件の判断に必要な記録と表示

2026年11月27日に依頼者が承認した5件を必須要件とする。対象は、修正結果と前回との差を読む人、課題を観測と照合する担当者、依頼を受け付けた操作者である。

| 要件 | 利用者の要求 | 受入条件 |
| --- | --- | --- |
| R-081 | 試した修正に効果があったかを知りたい。 | 修正案の段階、修正後の再検証成功、再検証失敗、判定不能を判断画面とモニターで読み分けられる。失敗した課題は対応中として残り、次に確かめることが分かる。 |
| R-082 | 同じ場所で起きた別々の課題を前回と比べたい。 | 同じファイルに前回はA・B、今回はB・Cがあるとき、Aは今回の記録から消失、Bは継続、Cは新規となる。Aの修復を推定しない。 |
| R-083 | 課題を取り込んだ後、照合ができる状態か知りたい。 | 課題1件・観測0件では観測の取込待ち1件と必要な入力を表示する。観測を取り込んで照合した結果がずれ0件のときは、その結果を読み分けられる。 |
| R-084 | 受付IDを使って後から監査結果を開きたい。 | 同名で別IDの受付を2件作り、指定した受付だけを既存監査と結べる。各受付IDで対応先または未連結を確認できる。受付登録だけでは監査を開始しない。 |
| R-085 | 自分の案件に該当する類型で、製品がどこまで実証されているか知りたい。 | 5類型ごとに固定データでの評価と実ラボでの修復・再検証の実績を読める。未検証の欄が分かり、表示の根拠を確認できる。 |

R-081は[R-055・R-060](REQUIREMENTS-EXTENSION.md)、R-082は[前回比較](SPEC-DUAL-VIEW.md)、R-083は[課題と観測の照合](../tasks/TASK.tracker-evidence-11-26-2026.md)、R-084は[受付の契約](API-CONTRACTS.md)、R-085は[R-059](REQUIREMENTS-EXTENSION.md)と[製品検収](../PRODUCT-ACCEPTANCE.md)に基づく。[仕様と検収例](SPEC-CASE-DECISIONS.md)
