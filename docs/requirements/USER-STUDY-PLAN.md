# 理解・行動試験の計画案（撤回済み）

本稿は2026-11-07のユーザー訂正により撤回した履歴である。実利用者試験、人数・正答率の合格条件、実利用者の募集、人間の試験の実施を製品完成の必須条件から外した。以下の内容は撤回時点の提案案として保持し、未実施の試験を合格扱いにしない。実施する場合は任意の検証として扱う。

ITパスポート程度の知識がある利用者が、画面から問題、根拠、対策、未確認事項を読み取り、次の行動を選べるか確かめる。[追加受入条件](ACCEPTANCE-EXTENSION.md)のR-061（撤回済み）に対応する。人数と合格条件は承認前の提案であり、外部標準が定めた値ではない。

## 人数と合格条件の提案

参加者は実利用者10名とする。製品の設計・実装・採点基準の作成に関わった人は含めない。ITパスポート程度の用語理解があり、脆弱性診断を専門業務にしていない人を対象とする。資格保有は必須にしない。

各課題は10名中8名以上の正答を必要とする。課題ごとの結果で判定し、全課題の平均では補わない。危険な誤認は全参加者・全課題を通して0件を必要とする。所要時間は診断用に記録し、今回の合否基準にはしない。

欠席、未回答、AIによる回答、試験中に答えを教えた記録は合格人数に算入しない。10名分の有効な回答がそろうまでは判定保留とする。有効な回答の誤答を、結果が悪いという理由で除外してはならない。画面や課題を修正して再試験する場合は、版と結果を別に残し、未参加の利用者を対象にする。

## 課題と採点

参加者には画面と課題だけを渡し、次の採点表は渡さない。選んだ行動と、その理由を自由記述で記録する。画面にない知識や、用語の丸暗記は採点しない。

| ID | 課題の場面と質問 | 正答に必要な説明・行動 | 危険な誤認 |
| --- | --- | --- | --- |
| U1 | 一部の類型が未実施の画面。この対象を安全だと言えるか | 未実施の範囲は判断できず、必要な調査を追加する | 未実施だから脆弱性なしと断定する |
| U2 | CVEが候補で、適用条件が未確認。どう扱うか | 対象製品、版、発生条件と根拠を確認してから確定する | 候補を確定済みと扱う |
| U3 | 同じ原因への試行が3回、検知が1件。何件の問題か | 原因として1件、試行は3回と区別する | なし。件数誤りは通常の誤答とする |
| U4 | CVSSは算出済み、業務影響の一部は未確認。優先度を決められるか | 技術的重大度と業務影響を区別し、未確認の業務条件を担当者に確認する | CVSSだけで業務影響や対応優先度が確定したと扱う |
| U5 | 修正案があるが、適用も再検証も未実施。解決済みか | 未解決と判断し、適用・攻撃遮断・正常動作などの確認を求める | 修正案があるだけで解決済みと扱う |
| U6 | ラボ再検証は成功、運用への反映は承認待ち。次に何をするか | 対象環境と証拠を確認し、運用への反映は別の判断として扱う | ラボ成功だけで本番変更が承認・実施されたと扱う |
| U7 | 対象版が変わり、画面に古い証跡と未確認範囲がある。どう報告するか | 旧版の結果と現在の未確認範囲を分け、現在の版で再確認する | 古い証跡で現在の安全性が保証されたと扱う |

正答は表の必要条件をすべて説明できた場合だけとする。言い換えは認める。理由が曖昧で必要条件を満たすか判断できない回答は、採点者が根拠を記録して未確定にし、勝手に正答へ補完しない。未確定の回答はユーザーが指定する別の採点者が同じ採点表で確認する。元の採点、再採点、根拠、確定者を保存する。集計開始から5営業日以内に確定できなければ、理由と未確定件数を示して判定保留にする。回答を見て採点表を変更する場合は新しい試験として扱う。

U3の画面には「同じ原因の問題は1件として数え、試行回数は別に表示します」と表示し、実際の「原因1件・試行3回」の表示と合わせて回答できることを、参加者へ渡す前に確認する。

## 実施と記録

1. 人数と合格条件の承認後、製品の版、画面、7課題、採点表をハッシュで固定する。回答を見てから基準を緩めない。
2. ユーザーが手配した参加者に、匿名IDを割り当てる。名前、メールアドレス、勤務先は収集しない。エージェントから募集連絡は行わない。
3. 同じ説明を読み上げる。「画面に表示された内容をもとに、次にすることと理由を答えてください。分からない場合は分からないと答えてください。」試験中に答えや判断を誘導しない。画面に備わる用語説明は利用できる。
4. 回答には匿名ID、人間による回答か、助言の有無、理由、所要時間、製品と計画のハッシュを残す。採点者は各課題の正誤、危険な誤認の有無、その根拠を記録する。AI利用と助言は事前に不使用を依頼し、終了時の本人申告と実施担当者の観測記録で確認する。文章の印象やAI判別器で推測して除外しない。申告と観測が食い違う場合はユーザーが両記録を確認し、解消できなければ未確定とする。除外理由も匿名で保存する。
5. ユーザーから記録を受け取り、課題別の有効人数、正答人数、危険な誤認数、保留理由を集計する。AIによる試走と、実利用者の結果を分ける。

人数・基準が未確定、回答が未受領、または基準未達の間は製品完成と判定しない。技術試験の成功でこの試験を代替しない。

（2026-11-07のユーザー訂正により、本節の完成条件としての効力は撤回した。未実施の試験を合格扱いにしない原則のみ、任意の検証として実施する場合に適用する。）
