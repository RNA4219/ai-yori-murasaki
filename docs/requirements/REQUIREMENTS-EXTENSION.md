# 要件拡張 R-051〜R-063（追加提案の確定稿）

本稿は[既存要件 R-001〜R-050](../requirements/REQUIREMENTS.md)を維持したまま、受領レビューの追加提案R-051〜R-063を要件として確定するものである。番号は受領レビューの提案番号を保持する。既存要件の削除・先送り・緩和は行わない。特にR-046（ATT&CK/KEV/EPSSはv1 MUST）は維持する。

製品コードは本稿の対象外であり、本稿は製品の実装済み・完成を意味しない。現在、製品は未完成である。データスキーマ・画面・APIの実装仕様は本稿に書かない（後続工程）。

関連: [Task 20261107-03](../tasks/TASK.product-clarity-11-07-2026.md) / [既存要件](../requirements/REQUIREMENTS.md)

## 0. 適用条件（全要件共通）

- 帰属: U（ユーザー逐語要求）/ S（監督設計判断）/ R（原レポート由来）を各要件に記す。
- 義務: MUST / SHOULD。
- 維持条件: Red/Blind Blue/Purpleの分離、独立Oracle（R-014、例外なし）、RSIゲート（R-042）、認可境界・隔離・承認ゲート（R-020/R-023/R-034/R-035）、証跡（R-029〜R-033）、7adapter（R-040）を維持する。
- 契約試験と実接続（live）を区別し、契約通過を接続済みと表示しない（R-019）。
- 実行失敗・判定不能を未検出・安全と同義にしない（R-016）。
- 分類体系（CWE/CVE/OWASP/ATT&CK/CVSS/KEV/EPSS）は独立に扱い、根拠不足時は候補・未特定を許す。CWEからATT&CKを自動確定しない。
- 同一原因への複数試行は1 Findingへの複数Attemptであり、複数類型・複数脆弱性として数えない。
- 既存データの互換と版変更時の無効化を条件とする（R-062）。
- ユーザー承認済みの追加項目: (A) CVSS算出/業務影響、(B) 最低5類型評価。(C) 実利用者試験は、2026-11-07のユーザー訂正により必須要件から外した（R-061参照）。人数・正答率の合格条件、実利用者の募集、人間の試験の実施を製品完成の必須条件としない。
- 試験の成功判定は、事前に固定した合格基準の達成を要する。記録の存在のみでは成功としない。

## 1. 追加要件

### R-051 調査範囲（Coverage）の明示
- 根拠: U（未確認を隠さない説明）、R（原レポートの範囲明示）、S（R-002/R-044の具体化）
- 義務: MUST
- 内容: 対象・類型・実施/未実施・未実施理由・対象版を記録し、未調査範囲を安全と読める表示にしない。
- 受入条件: 各campaignで対象・類型・実施/未実施・理由・版が台帳に残り、HTMLで未実施が未検出と区別表示される。
- 依存: R-002, R-024, R-044
- v1対象: v1

### R-052 分類根拠の独立記録（CWE/CVE/OWASP/ATT&CK）
- 根拠: U（類型説明の要求）、R（原レポートのCVE/attack_mapping）、S（R-046是正）
- 義務: MUST
- 内容: Findingごとに分類根拠を独立記録する。CWEは原因分類、CVEは公開脆弱性識別、OWASPは説明・手順、ATT&CKは観測行動として区別する。CVEは対象製品/版/条件の適合が確認できるときのみ付与し、全Finding必須としない。CWEは根拠不足なら候補/未特定を許す。自作の認可不備に類似CVEを付与しない。CWEからATT&CKを自動確定しない。
- 受入条件: 各Findingに分類根拠または未特定理由が記録され、CVE付与時は適合確認の根拠が併記される。未特定が未検出と混同されない。
- 依存: R-002, R-008, R-025, R-040, R-046
- v1対象: v1

### R-053 観測・原因・反証の分離
- 根拠: U（事実と推測の区別）、R（原レポートの証拠主義）、S（R-013/R-030の具体化）
- 義務: MUST
- 内容: 観測事実（Observation）、原因の推測（Claim）、反証・訂正の記録を区別する。推測を確定事実として表示しない。
- 受入条件: Findingに観測・推測・反証の区別があり、推測のみのFindingが確定と表示されない。
- 依存: R-013, R-016, R-030
- v1対象: v1

### R-054 判断ごとの確かさの分離
- 根拠: U（分かりやすい説明）、S（R-003/R-016/R-044の具体化）
- 義務: MUST
- 内容: 検出確認・原因確定・影響評価・重大度評価の確かさを別軸で保持する。検出確認を原因・影響・重大度の確定と同一視しない。LLM生成の確信度を根拠にしない。
- 受入条件: 各軸の状態が台帳・HTMLで別表示され、検出確認済みでも重大度未評価と表示できる。
- 依存: R-003, R-016, R-044
- v1対象: v1

### R-055 修正案と再検証の区別
- 根拠: U（修正案で解決済みと表示しない）、S（R-011/R-016/R-044の具体化）
- 義務: MUST
- 内容: 修正案の生成・適用・再検証を別状態とし、適用環境と版を記録する。HTTP 403のみで修復成功としない。修復成功は修正適用・不正操作不成立・正常操作継続・関連テスト通過・Oracle判定可能証拠・版と未検証範囲記録のANDとする。修復による副作用がある場合、またはOracleが判定不能の場合は修復成功としない。技術的な修復成功と組織としての適用承認（PR承認ゲート）は別に保持する。
- 受入条件: 修正案のみの状態が解決済みと表示されず、AND条件を満たさない限り修復成功と表示されない。副作用がある場合・Oracle判定不能の場合は修復成功と判定されない。技術的修復成功が組織的承認の完了として表示されない。
- 依存: R-011, R-016, R-020, R-044
- v1対象: v1

### R-056 CVSS算出と業務影響の評価（追加承認A）
- 根拠: U（追加3項目の承認）、R（原レポートの優先付け）、S（R-008/R-046の拡張）
- 義務: MUST（v1に含める。ユーザー承認済み）
- 内容: CVSS v4.0を採用し、算出機能と業務影響の評価を実装する。計算の詳細仕様は後続工程で確定する。CVSS閾値から業務優先度を自動確定しない。重大度と業務上の優先順位を分離し、KEV/EPSS（R-046）と併存させる。
- 受入条件: CVSS算出結果と算出根拠（ベクター等）が記録され、業務優先度が自動確定されないことが確認できる。KEV/EPSS統合が維持される。
- 依存: R-008, R-046, R-052
- v1対象: v1

### R-057 初心者向け説明（判断支援）
- 根拠: U（ITパスポート程度で理解できる説明）、S（R-044/R-050の具体化）
- 義務: MUST
- 内容: 問題・場所・影響・根拠・対策・再確認・不明点を提示し、非専門家が次の行動を判断できるようにする。説明層は評価層の投影であり代替しない。色だけで区別せず状態名と短い説明を併記する。
- 受入条件: 1campaignの終端までHTMLで追跡でき、未確認・HOLD・未検出・修正案・再検証済みが区別表示される。
- 依存: R-044, R-050, R-054, R-055
- v1対象: v1

### R-058 連携の実際の状態の区別
- 根拠: U（契約通過を接続済みと表示しない）、S（R-019/R-024/R-040/R-049の具体化）
- 義務: MUST
- 内容: 接続・実行・取得・検証を別状態として記録・表示する。7系統（R-040）を維持し、契約試験通過を実接続済みと表示しない。未取得・PATH不在は接続不可として明示する。
- 受入条件: HTML・台帳で契約試験と実接続が別状態として表示され、未接続がPASSと表示されない。
- 依存: R-019, R-024, R-040, R-049
- v1対象: v1

### R-059 最低5類型での評価（追加承認B）
- 根拠: U（追加3項目の承認）、R（原レポートの類型評価）、S（R-017/R-018/R-042の拡張）
- 義務: MUST（v1に含める。ユーザー承認済み）
- 内容: 認可、SQLi、XSS、パストラバーサル、既知依存脆弱性の5類型を最低評価集合として固定する。5類型は製品の検査機能全体の上限ではない。各類型に正例・負例・未見集合・型別成績・正常回帰を含める。正例と負例を分け分母を固定し、見逃しも未検知として保存する。実行失敗は未検出や安全と同義にしない。固定benign suiteのFP0はR-018に従い、未知環境のprecision保証にしない。型別成績はRecall・Precision・誤分類率・根拠充足率・修復成功率・正常動作維持率・判定不能処理率で評価し、指標定義と分母を事前固定する。重大な誤判定、認可境界の突破、根拠の捏造、正常系破壊は、総合スコアが高くても完成を阻止する。
- 受入条件: 5類型それぞれに正例・負例・未見集合・型別成績・正常回帰の記録があり、実行失敗が未検出と区別される。型別成績が事前固定した指標定義・分母に照合され、重大な誤判定・認可境界突破・根拠捏造・正常系破壊がある場合は総合スコアにかかわらず完成と判定されない。
- 依存: R-017, R-018, R-042, R-048, R-052
- v1対象: v1

### R-060 状態意味の統一
- 根拠: U（状態の混同防止）、S（R-016/R-024/R-044の具体化）
- 義務: MUST
- 内容: 未調査・未検出・確認済み・修正済み・再検証済みを区別し、再検証済みには結果（解消確認/継続/判定不能）を併記する。問題の疑い・誤検知・実行失敗・HOLDも別状態とする。調査状態・確認状態・修正状態・再検証状態・適用環境を別々に保持する。
- 受入条件: 台帳・API・画面で状態語彙の意味が一致し、未調査と未検出、修正案と修復完了が区別表示される。
- 依存: R-016, R-024, R-044
- v1対象: v1

### R-061 実利用者試験を完成条件に含める（追加承認C・2026-11-07ユーザー訂正により撤回）

- 内容: 実利用者試験、人数・正答率の合格条件、実利用者の募集、人間の試験の実施を、製品完成の必須条件としない。試験未実施を完成阻止理由にしない。実施する場合は任意の検証として扱い、AIによる代役を実測と記録しない点は維持する。
- 受入条件: なし（必須要件としての受入条件は撤回）。R-057の初心者向け表示要件は維持する。

### R-062 判断までたどれる記録と版管理
- 根拠: U（追跡可能な提示）、S（R-017/R-029〜R-031/R-048の具体化）
- 義務: MUST
- 内容: 要件から検査・観測・判断・修復・再検証まで根拠を追跡できるようにする。既存データの互換を維持し、版変更時は前バージョンの検証結果を無効化し明示する。無効化は旧検証結果の有効性ラベル変更であり、証跡レコードの削除ではない（R-029〜R-033の証跡保存義務と両立する）。文書リンクの存在を実行証拠の接続と同一視しない。
- 受入条件: 要件→テスト→証跡の追跡が可能で、版変更時に旧検証結果が旧版限定・無効として表示され、証跡レコードは保持される。
- 依存: R-017, R-029, R-030, R-031, R-048
- v1対象: v1

### R-063 MIT公開の準備
- 根拠: U（MIT指定）、S（R-033/R-045の具体化）
- 義務: MUST
- 内容: 配布物に秘密情報を含めず、第三者権利表示と外部依存を示す。MIT公開は自身コードの利用許諾であり、第三者システムへの検査権限ではない。R-045の「対外公開をGoalに含めない」と両立させ、公開準備と公開操作を分離する。
- 受入条件: LICENSEがMITで、配布物の秘密情報混入チェックと権利表示の記録がある。公開操作は行わない。秘密情報混入チェックの対象範囲・方法・記録様式は後続工程で確定する。
- 依存: R-033, R-045
- v1対象: v1（準備）。公開操作は対象外。
