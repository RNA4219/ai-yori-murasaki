# 実行・証跡保全

個別調査と完全監査に共通する。対象コードの実行、証跡保存、委任の書き込み先設定に入る前に読む。元のSKILL.mdの「Universal execution safety」「Full audit setup / Write isolation」を切り出したもの。

## 対象コードを動かす条件

JSON検証器のCLIにもOS依存条件がある。開始前に`node -p "JSON.stringify({noFollow:require('node:fs').constants.O_NOFOLLOW,nonBlock:require('node:fs').constants.O_NONBLOCK})"`で、両方が0でない整数として使えるか確認する。Windows版Nodeなどで不足する場合、同梱CLIは入力を受け付けず停止する。読み取り保護を外して回避せず、対応するLinuxなどの環境で検証器を使う。これはJSON入力保護の確認であり、対象コードを実行できる隔離環境の証明ではない。

ソース閲覧は読み取りのみ。対象が制御するビルド、テスト、プロセス、ブラウザー、エミュレーター、ファザー、fixture処理は、次の条件をすべてOSで強制できる隔離環境でだけ実行する。

- 外部通信を遮断する。ローカルのクライアント／サーバー検査が必要な場合だけ、隔離したloopback名前空間を使う。
- 空の環境変数から、明示した許可リストと安全な値だけを設定する。ホーム、テンポラリー、キャッシュはscratch内に置く。
- 対象とツールチェーンは読み取り専用にし、対象プロセスの書き込みは割り当てた`scratch/`内だけに許可する。
- CPU、メモリー、プロセス数、ファイルサイズ、ディスク使用量、経過時間に明示的な低い上限を設ける。

ビルドがソースの隣へ書く必要がある場合、エージェントは対象プロセスの外側から、割り当てたscratch内に使い捨てのコピーを作れる。対象へ既存の出力、別担当の領域、ホストのホーム、認証情報、ソケット、共有サービスを公開しない。依存物をインストール・取得せず、手元にあるツールと依存だけを使う。条件を強制できなければ実行せず、不足する機能と安全な確認計画を要検証として返す。

ダミーの主体・資源・秘密値を使う。配備先、外部サービス、共有基盤、本番の認証主体、他人のデータ、ライブの管理系に診断の通信を送らない。実環境や共有プロセスの可用性試験、成果物の公開、リリース変更、有料APIの消費、最小の境界違反を越えた追試を行わない。決定的な事実がソースや隔離fixtureの外にあるなら、要検証にする。

## 出力と所有者

完全監査では、絶対パスでスキル、対象、安定したrepo名、出力先、コミットと作業ツリーの状態を確定する。既定の出力先は対象外の`~/security-audit-skill/<repo-name>/run-<N>`で、次の未使用の整数を使う。対象内の出力は、利用者がその場所を明示し、親がディレクトリ全体をGitのignore対象と確認した場合だけ使う。それ以外は外部パスを確認する。未レビューの変更・生成物を別リビジョンと扱わない。

親だけが次の共有ファイルを書く：`run-metadata.json`、`architecture.md`、`coverage-ledger.json`、`findings.json`、`REPORT.md`、`FINDINGS-DETAIL.md`、`NEEDS-VALIDATION.md`。

各探索者・検証者には`<output-dir>/agents/<agent-id>/scratch/`と親所有の`artifacts/`を分ける。IDは`^[a-z0-9][a-z0-9_-]{0,63}$`に一致させ、Windowsのデバイス名`con`、`prn`、`aux`、`nul`、`com1`〜`com9`、`lpt1`〜`lpt9`を使わない。小文字で大文字小文字の衝突を防ぐ。担当と対象プロセスはscratchだけに書く。共有ファイル、対象ソース、保存済み証跡、他担当の領域を変更しない。`/tmp`やホストのホームを代替の書き込み先にしない。

個別調査では対象が制御するファイルを保存しない。完全監査で最小の非秘密の結果を保存するときだけ、信頼できる親側コードが以下の昇格を行う。artifactsを対象の隔離環境に公開しない。

## 親側だけが行う証跡昇格

実行前に、親はscratchとartifactsの信頼できる非継承ディレクトリ記述子を開いて保持し、予定するscratch相対ファイル、個別・合計バイト上限を許可リストへ記録する。記述子は担当や隔離環境へ渡さない。隔離環境とその全プロセスが終了してから、ファイルを一つずつ処理する。

1. 宣言した相対パスについて、絶対パス、空、`.`、`..`、シンボリックリンク成分を拒否する。
2. 保持したscratchルート記述子から、リンクをたどらないディレクトリ相対操作で親成分を歩く。パスで開き直さない。
3. 末尾をno-followかつnonblockingで開く。
4. `fstat`で通常ファイル、リンク数が正確に1、個別・合計上限以内であることを確かめる。
5. その記述子からの読み込み中にも上限を強制する。
6. 検証したサイズだけをコピーし、再び`fstat`して同一性・型・リンク数・サイズの変化を拒否する。
7. 保存先も保持したartifactsルート記述子から全親成分をno-followで歩き、実ディレクトリと確認する。未存在のディレクトリは排他的に作り、no-followで再度開いて検証する。
8. 末尾をリンク非追跡・排他的に作り、通常ファイルでリンク数1と確認する。検証済みの入出力記述子を開き直さずコピーする。
9. POSIX以外では同等の競合耐性を持つAPIを使う。
10. scratchの再帰コピーやglob、artifacts内でのアーカイブ展開をしない。リンク、FIFO、ソケット、デバイス、ディレクトリ、ハードリンク、変化するファイル、上限超過ファイルは開かず昇格しない。
11. いずれかの検査が利用不能・強制不能・失敗なら、そのscratch項目を採用しない。決定的な証拠なら、正確な昇格の障害を`needs_validation`に残す。

[HUNTING.md](HUNTING.md)と[VALIDATION-AND-REPORTING.md](VALIDATION-AND-REPORTING.md)には、この順序と条件に対応する同一の英語プロンプトブロックがある。探索者・検証者のプロンプトへ渡す際は、そのブロックを逐語でコピーする。

再現した検査は、コマンド、正確な入力、隔離の上限、再現に必要な許可済み環境変数名と非秘密の値だけを記録する。ホストの環境全体、継承値、認証情報、認証状態、無関係なパスを取得・コピーしない。実行後の伏字処理ではなく、空の環境から起動する。

委任前に親が`run-metadata.json`を書く。最低限、`run_id`、`repo`、`target`、`source_ref`、`profile`、`scope_paths`、`budget`（未指定ならnull）、`execution_policy: "sandboxed-source-and-local-only"`、選んだ分野別ファイル、前回結果のパス、共有ファイルの所有者、`run_status: "in_progress"`を含める。これらの事実が変わるときだけ更新し、候補の状態は台帳とfindingsに置く。
